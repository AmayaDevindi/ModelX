# 09 – Competition rules (booklet summary)

Source: https://modelx2.pages.dev/ (checked 15 Oct 2026). If this summary and the booklet disagree, the booklet wins.

## The challenge
Build a system that tells people something they couldn't work out alone – a pattern, risk, trend or anomaly. **Just showing data back (retrieval) doesn't count as insight.** The output must be trustworthy, show what the data can't support, and fail safely. Any method is allowed. Our domain: Economy & livelihoods.

## Submission 1 – proposal (every part must be properly answered)
1. Problem, who it affects, target user
2. Existing solutions and why they don't work for this user
3. Proposed solution and methodology
4. Data: sources, how we extract it, historical/recent/live, right to use
5. Evaluation: how we judge success, and what we do if it fails

## Submission 2 – implementation
- Technical report: architecture, stack and why, honest evaluation against the proposal, data actually used (how current, gaps)
- **Public** git repo with a README explaining how to run it (private repo = no submission)
- Two-page summary
- Three-minute video of the system working on real data

## How we're judged
**Implementation (cut to 15):** data work 30% (sourcing, extraction, how current, cleaning, gaps, ethics, licensing) · insight 25% · engineering 25% (structure, dependencies, *sustained git history*, report matches the code) · demo 20%

**Final:** working live 35% (including how it handles what it doesn't know) · insight value 25% (would a user act on it?) · problem significance 20% · depth under questioning 20%

**Best Data Vision award:** where the data came from, how we got it, and whether it's current enough to act on.

## Rules
- Original work made during the competition. Plagiarism or a pre-built system = disqualified.
- Open-source libraries, pretrained models and public data are fine – credit them.
- AI use is allowed but must be disclosed (which tools, for what). "The model wrote it" is no excuse – we must understand everything.
- Data must be licensed, covered by terms of service, or documented as permitted. Respect robots.txt. Minimise and anonymise personal data. No deception.
- Deadlines are firm – a missed gate means elimination.
